# Паспорт дашборда «Салон красоты»

Документ описывает структуру панели, источники данных, формулы всех метрик и допущения.
Назначение: ответить на вопрос «откуда взялась цифра» без изучения чартов.

## 1. Источники данных

### Таблица `visits` — визиты клиентов

| Колонка | Описание |
|---|---|
| `visit_id` | Уникальный номер визита |
| `date` | Дата визита |
| `time` | Время визита |
| `cabinet` | Кабинет (например, «Кабинет 2») |
| `master` | Имя мастера |
| `service` | Услуга (например, «Чистка лица») |
| `duration_min` | Длительность визита в минутах |
| `client_id` | Идентификатор клиента |
| `client_type` | Тип клиента: «Новый» / постоянный |
| `status` | Статус визита: «Завершён», «Отменён клиентом», «Неявка» и др. |
| `revenue_services` | Выручка от услуг за визит |
| `revenue_retail` | Выручка от розничных продаж за визит |
| `payment_method` | Способ оплаты («Карта» и др.) |
| `rebook` | Признак повторной записи (0/1) |

### Таблица `schedule` — расписание и доступные часы мастеров

| Колонка | Описание |
|---|---|
| `master` | Имя мастера |
| `date` | Дата рабочего дня |
| `hours_available` | Доступные часы мастера за день |

### Датасет «Загрузка и продуктивность»

Собран одним JOIN-запросом (см. раздел «Ключевой JOIN»). Колонки:

- `master` — имя мастера (из schedule)
- `date` — дата рабочего дня (из schedule)
- `staffed_hours` — доступные часы мастера за день (из schedule)
- `visits_count` — количество завершённых визитов мастера за день (COUNT из visits)
- `revenue` — выручка мастера за день: услуги + ритейл (SUM из visits)
- `busy_hours` — занятые часы мастера за день (SUM(duration_min) / 60.0)

На основе этого датасета построены метрики 10–13 и четыре Big Number карточки.

---

## 2. Ключевой JOIN (датасет «Загрузка и продуктивность»)

```sql
SELECT
  s.master,
  s.date,
  s.hours_available AS staffed_hours,
  COUNT(DISTINCT v.visit_id) AS visits_count,
  SUM(COALESCE(v.revenue_services, 0) + COALESCE(v.revenue_retail, 0)) AS revenue,
  SUM(COALESCE(v.duration_min, 0)) / 60.0 AS busy_hours
FROM schedule s
LEFT JOIN visits v
  ON s.master = v.master
 AND s.date = v.date
 AND v.status = 'Завершён'
GROUP BY s.master, s.date, s.hours_available
```

Пояснения:
- **LEFT JOIN** — дни без визитов не теряются: строка остаётся, значения будут 0.
  Это важно, чтобы «доступные часы» не завышали загрузку в пустые дни.
- **COALESCE(..., 0)** — страховка от NULL в выручке и длительности.
- **Фильтр `status = 'Завершён'`** — в занятость и выручку идут только завершённые визиты.
- Статус в данных называется ровно «Завершён» (проверено на фактических данных).

## 3. Формулы метрик

### Финансовый блок

**1. Выручка**
- Формула: `SUM(revenue_services) + SUM(revenue_retail)`
- Пояснение: суммарная выручка по визитам (услуги + розничные продажи).

**2. Средний чек**
- Формула: `SUM(revenue_services + revenue_retail) / COUNT(DISTINCT visit_id)`
- Пояснение: выручка за период, делённая на число визитов. COUNT(DISTINCT) защищает
  от двойного учёта, если визит вдруг задублируется в данных.

**3. Доля ритейла**
- Формула: `SUM(revenue_retail) * 100.0 / NULLIF(SUM(revenue_services + revenue_retail), 0)`
- Пояснение: какой процент выручки приносят продажи товаров. NULLIF страхует от деления на ноль
  (пустые периоды не сломают чарт).

**4. Визиты за день**
- Формула: `COUNT(DISTINCT visit_id)`
- Пояснение: количество уникальных визитов за выбранный период.

### Клиенты

**5. Доля новых клиентов**
- Формула: `SUM(CASE WHEN client_type = 'Новый' THEN 1 ELSE 0 END) * 100.0 / COUNT(DISTINCT visit_id)`
- Пояснение: процент визитов новых клиентов от общего числа.

**6. Rebook rate (запись)**
- Формула: `SUM(rebook) * 100.0 / COUNT(DISTINCT visit_id)`
- Пояснение: процент визитов, после которых клиент записался повторно. Ключевой индикатор удержания.

**7. Отмены и неявки**
- Формула: `SUM(CASE WHEN status IN ('Отменён клиентом', 'Неявка') THEN 1 ELSE 0 END) * 100.0 / COUNT(DISTINCT visit_id)`
- Пояснение: процент потерянных визитов (клиент отменил или не пришёл).
- Внимание: названия статусов берутся из данных как есть — при смене справочника статусов формулу надо обновить.

### Загрузка и продуктивность (метрики 10–13, датасет «Загрузка и продуктивность»)

**8. Загрузка мастеров по минутам**
- Формула: `SUM(duration_min)`
- Пояснение: суммарное занятое время мастеров в минутах за период.

**9. Новые vs постоянные клиенты**
- Формула: `COUNT(DISTINCT visit_id)`
- Пояснение: разбивка визитов по типам клиентов. Само число совпадает с метрикой 4 —
  различие даёт Group By по колонке `client_type` (настройка чарта, см. раздел «Ограничения»).

**10. Доля ритейла vs услуги**
- Формула: `SUM(revenue)`
- Пояснение: выручка из датасета «Загрузка и продуктивность» (услуги + ритейл за день).
  Совпадает с метрикой 1 по сумме за период — различие в разрезе: этот чарт разбивается
  по мастерам/дням через Group By (см. раздел «Ограничения»).

**11. Заполненность (Utilization)**
- Формула: `busy_hours / staffed_hours * 100`
- Значение: 62.8 %
- Пояснение: сколько процентов доступных часов мастера реально заняты визитами.

**12. RevPAH (выручка за час работы)**
- Формула: `revenue / busy_hours`
- Значение: ~3 000 ₽/час
- Пояснение: сколько выручки приносит каждый занятый час работы мастера.

**13. Продуктивность (выручка за доступный час)**
- Формула: `revenue / staffed_hours`
- Значение: ~4 780 ? за час доступного времени — фактически совпадает с метрикой 10
  в пересчёте (см. ниже).
- Пояснение: выручка на час расписание. В текущей конфигурации формула совпадает с метрикой 11:
  это не ошибка, а следствие структуры датасета (записано заранее, чтобы не искали «потерянную» разницу).

Санити-чек: RevPAH / Продуктивность = 62.8 % — совпадает с Utilization, что подтверждает
согласованность формул: \(1{,}59 \times 0{,}628 \approx 1\).

## 4. Допущения и ограничения

1. В метрики занятости, выручки и продуктивности входят только визиты со статусом «Завершён».
2. Доступные часы берутся из колонки `hours_available` таблицы `schedule`; расписание считается графиком мастера по умолчанию.
3. Выручка = услуги (`revenue_services`) + розница (`revenue_retail`). Себестоимость (COGS) в источнике отсутствует.
4. Удовлетворённость клиентов (CSAT) в источнике отсутствует: колонок с оценками в данных нет.
5. **Диапазон данных в источнике: с 01.09.2026 по 20.11.2026 (всего 1528 записей визитов).**
   Фильтр «Last 30 days» не показывает метрик, так как в этом окне отсутствуют или минимальны записи.
   Для отображения данных рекомендуется использовать период «Last 90 days» либо кастомный диапазон,
   покрывающий доступный период.
6. Статус «Завершён» в формулах записан текстом; при изменении справочника статусов формулы требуют обновления.

### Ограничения и планы

- **CSAT и COGS — не реализованы.** В источнике отсутствуют данные об оценках клиентов и себестоимости.
  Требуется расширение источника (опросы клиентов, данные закупок). Карточки удалены с дашборда (решение от 21.11.2026).
- **Метрики 9 и 10** используют ту же формулу, что 4 и 1 соответственно; различие даётся
  настройкой чарта (Group By по `client_type` / по мастерам и дням). Это отражено в пояснениях выше.

## 5. Структура дашборда

- **Фильтр по датам** (Time Range) — управляет всеми карточками; рекомендуемое значение по умолчанию: Last 90 days или Custom 01.09.2026–20.11.2026.
- **Финансовый блок:** Выручка, Средний чек, Доля ритейла.
- **Клиенты:** Визиты за день, Доля новых клиентов, Rebook rate, Отмены и неявки, Новые vs постоянные.
- **Загрузка и продуктивность:** 4 Big Number карточки (Заполненность, RevPAH, Продуктивность, Загрузка по минутам) + график «Все дни».
- Графики: динамика по дням (несколько серий), разбивки по мастерам.
